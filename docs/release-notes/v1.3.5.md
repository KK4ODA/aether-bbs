**Packet radio works again, settings apply when you save, and steadier links.**

## Packet radio (Soundmodem, Direwolf)

- **The AGWPE link works.** The BBS packed every AGWPE frame header as 40 bytes instead of 36, so
  Soundmodem and Direwolf could not understand it, and it could not read their replies. Packet
  sessions now work.
- **A dropped AGWPE link is noticed and comes back by itself.** Before, the packet session on it
  hung until a timeout, the card showed the link up, and only Restart recovered. Now the session
  ends, the card shows the link down, and the BBS reconnects (5 s, doubling up to once a minute)
  until the instance is stopped.

## Settings apply when you save

These used to need a restart and now take effect on **Save**:

- turning a modem instance on or off, adding, removing or renaming one;
- an HF instance's PTT, VARA HF's bandwidth and the BBS callsign (the modem restarts to use them);
- turning APRS-IS on or off;
- bulletin forwarding neighbours and the forwarding server;
- inbound email and the Winlink forward list;
- the update check interval.

Only the log settings (level, folder, file size) still need a restart, and Save says so.
Saving no longer restarts an Aether HF instance that has a control token when nothing changed.

## Steadier links

- The VARA, Aether HF, AGWPE, FLrig and APRS-IS links all retry with the same rules. A second
  dropped-link event while the BBS is already reconnecting no longer starts a second attempt.
- **Hamlib PTT:** if rigctld drops the connection, a PTT command that failed is sent again after
  reconnecting. Before, a lost "unkey" could leave the radio transmitting.
- Before an outbound call the modem gets the same setup commands as at connect (Aether HF
  missed one).

## BBS commands

- Listings (L, LB, FL) and long bulletins (RB) page the same way: Q at "-- More --" stops the
  listing, and there is no pause after a full last page.
